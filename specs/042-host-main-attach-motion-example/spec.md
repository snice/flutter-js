# Spec: 宿主 main.dart 定制附着、eject 路径修复与 @vueuse/motion 示例

- **ID**: 042-host-main-attach-motion-example
- **状态**: ready
- **日期**: 2026-09-12

## 1. 要解决什么

三个独立但都在"开发者拿到项目之后"路径上的问题：

1. **宿主 main.dart 无法定制**。`.fjs/flutter` 是托管宿主，`fjs run` 每次整个重写
   `lib/main.dart`，手工改动（加一个 `engine.host.register`、初始化一个 Flutter
   插件）在下次 run 时全部丢失；而模块 autolink 出来的 `register` 调用又和
   手工改动混在同一段 main() 里，想"只保留手改部分"没有边界。
2. **eject 后宿主 pubspec 路径全部失效**。生成的 pubspec 用 `../../../packages/...`
   这类相对路径指向仓库内的 Flutter 包（flutter_fjs 与各模块），`fjs host eject`
   只 `rename` 目录不修路径，宿主从 `.fjs/flutter`（两层）挪到 `flutter/`（一层）
   后 `flutter pub get` 直接找不到依赖。
3. **DOM 形状的动画库在 App 端没有落点**。`@vueuse/motion`（用户已装
   `^3.0.3` 并写好 `src/plugins/motion.ts`）的指令内部走 `el.style[key] = v`
   直接写样式，而 fjs 自定义渲染器里的 Element 只有 `id/tag/appendChild/
   removeChild/setText/setProps`，App 端 `v-motion` 无处落笔。spec 031 的
   anime.js 是靠"动普通对象"绕开的，motion 的指令模式绕不开。

## 2. 不做什么（Non-goals）

- 不做通用 DOM 兼容层：shim 只覆盖 `el.style` 的读/写子集（见 §3.3），
  不做 `getComputedStyle`、`classList`、事件模型。
- 不让托管宿主的 `pubspec.yaml` 变成用户文件——它继续每次生成
  （依赖集合本来就是 fjs 算出来的）；要手工改 pubspec 请 eject。
- 不支持 motion 的 drag / visibility 修饰器（要 Pointer Events 与
  IntersectionObserver，App 端没有）；示例不演示它们。
- 不改 op 协议、natives 表、事件契约。
- 不给 `fjs add` 增加 @vueuse/motion 配方（配方表注册表是另一件事）。

## 3. 用户可见的行为

### 3.1 项目级 `src/main.dart` 附着宿主

项目根 `src/` 下可以放一个可选的 `main.dart`（与 `main.ts` 同级），它是一个
**完整的 Dart 模块**，约定导出：

```dart
// src/main.dart — 每次 run 原样复制为宿主 lib/fjs_attach.dart，
// 无论宿主是否 eject。项目文件是唯一事实来源。
import 'package:flutter_fjs/flutter_fjs.dart';

Future<void> fjsAttachHost(FjsEngine engine) async {
  engine.host.registerAsync('demo.asyncStore', (args) async { /* … */ });
  // 初始化 Firebase / 推送 / 任何 Flutter 插件……
}
```

`fjs run` / `fjs host create` 时（**无论 managed 还是 ejected**）：

- 该文件被原样复制为宿主 `lib/fjs_attach.dart`，每次 run 覆盖；项目没有这个
  文件时，生成一个空实现；
- 宿主 `lib/main.dart` 在模块注册之后、`runApp` 之前调用
  `await fjsAttachHost(engine);`。

手工代码进版本库（`src/`），`.fjs` 清掉也不丢。

### 3.2 autolink 注入收进独立函数，main.dart 手改安全

生成的宿主从单文件变成三个文件，各自所有权清晰：

| 文件 | 所有权 | 生成策略 |
|---|---|---|
| `lib/main.dart` | 用户（手改安全） | 缺失才生成；`fjs host sync --force` 可强制重写 |
| `lib/fjs_autolink.dart` | fjs | 每次 run 重写（managed 与 ejected 都写） |
| `lib/fjs_attach.dart` | 项目 `src/main.dart` 的镜像 | 每次 run 覆盖（无源文件则写空实现） |

`fjs_autolink.dart` 形状（generated 头 + 模块 import + 一个函数）：

```dart
// generated by fjs — do not edit
import 'package:flutter_fjs/flutter_fjs.dart';
import 'package:fjs_iconmind/fjs_iconmind.dart';

void fjsRegisterModules(FjsEngine engine) {
  FjsIconmind.register(engine);
  FjsWebgl.register(engine);
  FjsWebview.register(engine);
}
```

`main.dart` 里原来内联的 `${registers}` 一段变成一行
`fjsRegisterModules(engine);`。由于 main.dart 的内容不再随模块增减变化，
托管宿主对它改为**缺失才写**：手工改动自然存活，不再被 run 覆盖。
ejected 宿主的 main.dart 缺这两处调用时（老项目升级），run 时幂等补上
（补 import + 补调用行，已存在则不动）。

无模块时 `fjs_autolink.dart` 照常生成（空函数体），main.dart 无需条件分支。

### 3.3 Element 补 DOM 形状的 `style` 对象（runtime）

自定义渲染器的 Element 增加一个惰性创建的 `style` 属性，DOM 写法子集：

```ts
el.style.opacity = 0.5;            // 索引写
el.style['line-height'] = '20px';  // kebab 名同样接受
el.style.transform = 'translateX(10px)';
el.style.opacity;                  // 索引读：返回已写入的值，未写过为 undefined
el.style.setProperty('opacity', '0.5');
el.style.getPropertyValue('opacity');
el.style.removeProperty('opacity');
```

写入必须走样式引擎的 inline 层（与 `:style` 绑定、`useCssVars` 合并的是
同一条记录，互相不覆盖），由样式引擎重算并跨桥；读返回 inline 记录里
已有的值（不做级联解析）。web 端是真 DOM，天然成立，不改。

之后 hello-fjs 里 `v-motion` 指令在 App 端可直接工作（motion 库只碰
`el.style[key]`，`requestAnimationFrame` runtime 已有）。

### 3.4 @vueuse/motion 示例页

`examples/hello-fjs/src/pages/example/motion.vue`，`<route>` 进现有分组
「动画演示」。至少三块，两端同源：

1. **入场 variants**：一组卡片 `v-motion` + `:initial/:enter`（延迟、弹簧），
   展示 stagger。
2. **点击弹性**：`v-motion` + `:pressed` / 手动 `useMotion` 切换 spring，
   展示弹簧参数差异。
3. **数值驱动**：`useAnimate` 或 motion value 组合，展示透明度/位移循环。

`examples/hello-fjs/package.json` 补回 `"@vueuse/motion": "^3.0.3"`
（lockfile 已有，package.json 条目缺失），`src/plugins/motion.ts` 已就位。

### 3.5 eject 修复 pubspec 相对路径

`fjs host eject` 在移动目录后，扫描 pubspec.yaml（`dependencies:` 与
`dependency_overrides:` 两段）里所有相对 `path:` 值：按旧目录解析出绝对
目标，再以新目录为基准重新计算相对路径（`../../../packages/x` →
`../../packages/x`）。指向移动目录内部的路径经同一算法自然不变。
eject 到空目录新建宿主的分支不受影响（本就按新位置生成）。

## 4. 两端约定（宪法 I）

| | Flutter | Web |
|---|---|---|
| style shim | Element 上惰性合成，写走样式引擎 inline 层 | 真 DOM 原生 `style`，零改动 |
| v-motion 示例 | 同一份页面源码，指令生效 | 同一份页面源码，指令生效 |
| 已知差异 | drag / visibility 修饰器不可用（无 Pointer Events / IntersectionObserver）；`el.style` 读不到级联值，只有 inline 记录 | 完整 DOM 语义 |

差异登记进 `docs/web.md` 或 `docs/css-compat.md` 的已知差异表。
